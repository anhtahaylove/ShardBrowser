# Open questions — ShardBrowser v0.2.x Team/Fleet Sync

> Trạng thái: **Consensus-approved design**. Architect `APPROVE` rồi Critic `APPROVE` đã được persist đúng thứ tự; mọi Hash32 local DDL column vẫn là `BLOB` exact 32 bytes. G2, implementation, commit và release chưa chạy trong artifact này.

## Đã chốt

- [x] Key hierarchy/slot model: `Tenant Root KEK -> immutable Fleet KEK generation -> per-snapshot DEK`. Snapshot envelope có exactly one `DekSlotV2` wrap DEK dưới FKEK `key_id` + generation. Device HPKE grants chỉ phân phối FKEK ngoài envelope; ordinary fleet device không nhận TRK.
- [x] Commitment direction: canonical `EnvelopeIntentV2` được tạo trước encrypt, không có ciphertext hash/size hoặc final-manifest commitment; mọi DATA/FINAL frame AAD bind exact `intent_hash`; detached exact `SignedSnapshotManifestV2` chỉ được tạo sau encrypt và bind intent/preamble/slot/ciphertext/head/instance/epoch claims.
- [x] Exact envelope/restore wire contracts: `DekSlotContextV2`, `DekSlotV2`, `EnvelopeIntentV2`, `RestoreEpochTransitionV2` và `RestoreEpochInclusionProofV2` là closed maps với exact fields/types/bounds/optionality/domains/versions/hash/TBS/container preimages. Merkle codec exact `PROFILE_HEAD_SET_MERKLE_V2` khóa sorted unique non-empty leaves, separate leaf/binary/unary domains, no odd duplication, numeric directions và exact proof-shape validation; golden-vector ready for n=1/2/3.
- [x] Provider-independent authorization byte schemas: prior five records plus exact `TenantRootKeyGrantV2`. Root grant pins RFC 9180 base mode tuple `(0,0x0020,0x0001,0x0003)`, canonical `info`, non-empty domain-separated AAD, raw 32-byte TRK plaintext, deterministic `root_key_id`, every HPKE/container equality column, one-time OOB `FirstRootSelfGrant`, exact idempotent `ROOT_GRANT_CREATE` request/stored response, deterministic readback by `replay_id`, existing/rotation issuer rules, generation create/ack/activate/revoke endpoints and revoke/rotation limits; no placeholder remains.
- [x] Minimal trust repair: coordinator process + integrity/freshness of live coordination/RBAC SQLite are the trusted control plane for sessions/roles/revocation/leases/generations/idempotency/audit. Ciphertext/signed artifact bytes in DB/blob/log/backup remain untrusted for confidentiality/artifact integrity and client-verified. Malicious/same-epoch rollback of live control-plane rows is outside guarantee; external epoch record does not solve it; no signed auth transparency invented.
- [x] Metadata privacy: profile/fleet labels là ciphertext; server chỉ thấy canonical origin/tenant locator, opaque IDs, membership, key/grant/head metadata, sizes và timing allowlist.
- [x] Pilot quota: 512 MiB per snapshot, kèm aggregate tenant quota, concurrent-upload cap, chunk cap, encrypted-spool reserve và minimum free-disk preflight; chỉ đổi bằng fixture/memory/disk/DoS evidence.
- [x] Lease partition: one current lease row, server time authority, renew chỉ khi chưa expiry. Browser đã chạy không bị kill; sau expiry là `offline_fork`, cấm start/relaunch và remote commit, không có grace token.
- [x] Legacy v1: quarantine + remote-off; không automatic migrate/scrub trong early v0.2.x.
- [x] Upload recovery: exhaustive deterministic matrix cho `OPEN`/`FINALIZING`/`READY`/`COMMITTED`/`QUARANTINED` × staging/immutable absent/valid/invalid × receipt absent/valid/invalid. Short/corrupt/mismatch => quarantine; successful readiness pass leaves zero `FINALIZING`; committed mismatch là security incident, không GC.
- [x] Exact mutation idempotency: `PROFILE_PUBLISH_CREATE`, `PROFILE_CHECKOUT`, `CREATE_UPLOAD`, `FINALIZE_UPLOAD`, `RELEASE_LEASE` và `LOCAL_UNBIND` have exact request + stored-response bytes. Publish-create atomically creates version 0 + initial lease/fence; response-loss replay returns identical bytes and never creates a second profile/lease/fence/upload/promotion/delete; expired checkout receipt requires new key after reconcile.
- [x] Schema parity/local DDL: upload and snapshot store immutable `snapshot_id` + `manifest_replay_id` with required UNIQUE/index/composite FK equality; root/fleet generation records are keyed by `server_instance_id`. All fleet device/recovery/rotation grants, uploads and snapshots reference the exact candidate key `(server_instance_id,tenant_id,fleet_id,generation,fkek_key_id)`. Local DDL adds exact root grant/generation tables, instance-keyed fleet state, operation/upload snapshot/replay mirrors and V2 transition/proof columns. Extracted DDL executes as 15 strict tables with integrity/FK clean; eleven local probes plus executable fresh/upgrade server migration probes cover column/index/FK mismatches.
- [x] Downgrade clone: original profile metadata + user-data phải durable-move khỏi mọi v0.1.28 discovery path và pass readback trước khi clone dùng new local ID/no Team or credential artifact. Complete pre-v2 config/profile/user-data restore là path riêng, sau đó archive/retire Team artifacts; không partial restore hoặc original quarantined in place.
- [x] Server restore reconciliation: exact signed transition/container + deterministic V2 Merkle proof are tenant-scoped and keyed by instance/tenant/epochs. Empty/duplicate/reordered leaves, wrong binary/unary direction/shape, missing/uncovered/cross-tenant proof reject before unquarantine.
- [x] Restore-epoch authority/order: exact checksummed/fsync'd `server_instance_id + restore_epoch` record trong operator identity root ngoài SQLite DB/blob backup/rollback scope là authority; `v2_server_state` và local epoch chỉ mirror/cache. Restore sequence là fsync candidate DB + tenant transition/proof set + preparation manifest → atomic external record replace/file+parent fsync → DB install → read-only verify → transactional mirror rebuild/readback. Missing/corrupt/behind external record, instance mismatch, hoặc external-ahead không có exact preparation/transition evidence fail closed; không lower/rebuild authority từ SQLite. Crash table bao phủ mọi point trước/sau fsync/replace/install/reconcile.
- [x] SQLite unsigned wire range: mọi current wire integer persisted/mirrored trong SQLite—fence/version/generation/offset/size/epoch/count/timestamps—accept đúng `0..9223372036854775807`; decoder và DDL cùng reject negative, `i64::MAX+1`, `u64::MAX`, noncanonical, REAL/TEXT coercion và wrap/clamp fixtures. Future full-U64 cần versioned fixed-width big-endian BLOB hoặc canonical decimal TEXT riêng.
- [x] Exact manifest/commit/receipt containers: `SignedSnapshotManifestV2` khóa payload bytes/hash + signature suite/version/signer/signature + internal signed-container hash + exact outer bytes/full hash. `CommitRequestV2` khóa domain/version, tenant/fleet/profile/upload/idempotency/lease/fence/base/intent/ciphertext, exact signed-manifest container bytes/hashes, instance/epoch, client nonce và canonical request hash. `CommitReceiptBindingV2` khóa exact request hash, snapshot/result version/head, lease-release outcome, instance/epoch, commit timestamp và receipt ID. Server/local persist exact bytes+hashes; close/reopen replay request và receipt byte-identical, không re-encode từ columns.
- [x] Handoff order/no drift: persisted Architect re-approve revision v6.1 → persisted Critic approve → durable consensus **đã hoàn tất** → bounded G2 → independent verifier PASS → production implementation. Follow-ups order remains unchanged. `docs/NEXT_V0.2_X_GOAL.md` remains a v0.1.28 superseded pointer, not execution/release authority.
- [x] Definition of done: G0–G7 pass xác nhận implementation completion. `P-OP` là production gate riêng và có thể blocked; khi blocked, artifacts/evidence bắt buộc ghi **non-production-ready** và cấm production-ready/release-ready claim, tag, publish, release hoặc production migration. Production-ready chỉ khi G0–G7 + `P-OP` pass và mọi release action vẫn cần yêu cầu riêng.
- [x] Delivery: v0.2.0 là internal foundation; Windows là Team runtime đầu tiên, macOS/Linux local-only tới khi platform credential-store tests pass.
